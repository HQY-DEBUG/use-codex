# 使用 ChatGPT

> 有关完整的文档索引，请参阅 [llms.txt](https://learn.chatgpt.com/llms.txt)。通过将 `.md` 附加到页面 URL 即可获得文档页面的 Markdown 版本。

<a id="go-from-idea-to-useful-result"></a>

## 从想法到有用的结果

ChatGPT 是一个 AI 智能体，您可以用自然语言与之交流：

<WorkflowSteps>
1. 从问题、想法、粗略笔记、文件或需要完成的任务开始。

2. 要求 ChatGPT 解释信息、提出想法、起草内容、研究主题、分析材料或创造新的东西。

3. 添加所需的上下文和工具，例如文件、Web 搜索、项目或插件。

4. 审查结果，纠正方向，并要求更改。您不需要完美的第一个提示或特殊命令。

</WorkflowSteps>

<a id="choose-how-you-want-to-work"></a>

## 选择您想要的工作方式

使用聊天来提问或来回交流。当您希望 ChatGPT 执行较大的任务并获得可审查的结果时，请在切换器中打开“工作”。当您需要开发人员视图或更多技术细节（尤其是软件开发）时，请选择 Codex。

| 当您想要 | 时选择 | 示例 |
| ------------ | --------------------------------------------- | ---------------------------------------------------------------------------- |
| 聊天 | 与 ChatGPT | 一起解决问题 提出问题、搜索网络、集思广益、起草消息、比较选项 |
| ChatGPT Work | 定义结果并获得可审查的结果 | 创建平台、分析文件、起草报告、制定项目计划 |
| Codex | 使用开发人员工具并查看技术细节 | 调试代码、运行测试、审查 PR、实现功能 |

使用聊天来提问、集思广益、起草或修改文本、总结文件、比较选项或澄清更大的任务。在 Codex 中，指向 **新聊天**，然后在该选项可用时选择 **快速聊天**。

当您需要完成的、可审查的结果时，请切换到 **工作** 并描述它应包含的内容。有关示例任务、提示和最佳实践，请参阅 [开始使用 ChatGPT Work](get-started-with-work.zh-CN.md)。

<a id="what-chatgpt-work-can-do"></a>

### ChatGPT Work能做什么

ChatGPT Work 可以计划任务、收集背景、使用工具并将工作进行到可以查看的结果。



> 插图：ChatGPT Work 比较供应商并生成可供查看的电子表格。



要求它：

- **研究和分析信息。** 搜索网络、浏览网站、比较来源、读取文件、分析数据并总结结果。
- **使用您的文件和工具。** 引入上传的文件、[项目](projects.zh-CN.md)、内存、ChatGPT 库，并安装 [插件](plugins.zh-CN.md)。插件可以提供连接的信息、可重用的工作流程和支持的操作。
- **创建完成的文件。** 起草并完善[文档、演示文稿、电子表格和 PDF 文件](artifacts-viewer.zh-CN.md)。查看结果，要求进行具体更改，然后下载完整的文件。
- **创作视觉和互动作品。** 生成或编辑 [图片](image-generation.zh-CN.md)，制作交互式 [可视化](visualizations.zh-CN.md)，并使用 [站点](sites.zh-CN.md) 构建或共享网站和应用程序。
- **跨网站和应用程序工作。** 使用 [浏览器](browser.zh-CN.md) 研究网站并与之交互。在桌面应用程序中，当这些功能可用时，请使用 [浏览器扩展](chrome-extension.zh-CN.md)、[电脑使用](computer-use.zh-CN.md) 和 [应用截图](appshots.zh-CN.md)。
- **运行代码并审查技术工作。** 运行代码和 shell 命令、分析数据、检查文件、[审查代码](code-review.zh-CN.md) 并使用您所选环境可以访问的仓库。
- **委派并继续较长的任务。** 在 [分智能体](agent-configuration/subagents.zh-CN.md) 之间拆分独立工作，跟踪其进度，并保持 [长时间运行的工作](long-running-work.zh-CN.md) 处于活动状态。
- **重复有用的工作流程。** 设置 [计划任务](automations.zh-CN.md) 进行重复工作并使用 [技能](skills-and-plugins.zh-CN.md) 重用工作流程。
- **讨论一项任务。** 在桌面应用程序中支持的计划上，使用 [ChatGPT 语音](features/voice.zh-CN.md) 开始工作、检查进度或更改方向。

功能取决于您的计划、平台、区域、部署和工作区设置。您的工作区管理员可以控制对 ChatGPT Work、插件、浏览器使用和网络访问的访问。 ChatGPT Work 和 Codex 共用 [使用限制](pricing.zh-CN.md)。

<a id="choose-cloud-or-local-work"></a>

### 选择云端或本地工作

在网络上，ChatGPT Work 在托管云环境中运行。在桌面应用程序中，您还可以选择任务运行的位置：

- **云：** 在隔离的托管环境中运行工作。关闭桌面应用程序并从 Web 或移动应用程序继续后，任务可以继续进行。云工作可以使用上传的文件、连接的工具和批准的网站。
- **本地工作：** 使用计算机上的文件、应用程序或浏览器。当为您的帐户或工作区启用时，本地工作可在桌面应用程序中使用。

ChatGPT 显示其进度并在需要信息或批准时暂停。在批准之前审查相应的操作，并在使用或共享之前检查最终结果。

### 在桌面上比较 ChatGPT Work 和 Codex

ChatGPT Work 和 Codex 具有重叠的功能。如果您更喜欢 Codex，您可以继续使用它进行研究、文档、演示和其他知识工作。当两者都可用时，桌面应用程序会更改界面以及智能体呈现其工作的方式。

<ToggleSection title="详细对比">

| 桌面应用程序 | Codex 桌面应用程序 | 中的差异 | ChatGPT
| ------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 从哪里开始 | 选择 **ChatGPT**，然后切换到 **工作** | 在产品选择器中选择 **Codex** |
| 您看到的聊天 | 查看通过网络和移动设备上的聊天开始的聊天，以及 ChatGPT Work 聊天 | 关注 Codex 聊天和开发项目 |
| 快速聊天 | 不可用 | 可用时，通过 Codex | 中的网络和移动设备访问 ChatGPT 聊天
| 技术细节 | 隐藏技术细节，如 Git 或 shell 命令 | 查看开发人员详细信息，包括 diff 和审查视图 |
| 智能体沟通 | 喜欢非技术语言和完成的输出 | 可以包含技术和实施细节 |
| 拉取请求窗格 | 使用 ChatGPT Work 时不可用 | 启用时可用 |

</ToggleSection>

<a id="talk-to-chatgpt-naturally"></a>

### 自然地与ChatGPT交谈

就好像您正在向一位乐于助人的同事解释该请求一样。说明您想要完成的任务，添加更改答案的详细信息，并描述您所需的格式。您的第一个提示只是一个起点 - 您可以添加上下文或使用后续消息优化结果。



**从简单开始：**

```text
帮助我计划一次 30 分钟的团队会议，讨论我们的新客户反馈流程。
```

**添加上下文：**

```text
帮助我计划一次 30 分钟的团队会议，讨论我们的新客户反馈流程。观众是以前从未见过该流程的客户支持团队。包括五分钟的提问时间，并以明确的后续步骤结束。
```

**选择格式：**

```text
为之前没有见过我们新的客户反馈流程的客户支持团队创建一个 30 分钟的议程。包括五分钟的提问时间，以明确的后续步骤结束，并格式化它，以便我可以将其粘贴到日历邀请中。
```

您可以继续执行简单的指示，例如：

- “把这个缩短一点。”
- “给我三种不同的方法。”
- “你做出什么假设？”
- “在继续之前先问我问题。”

了解有关 [提示](prompting.zh-CN.md) 的更多信息，或使用 [人工智能基础课程](https://academy.openai.com/home/courses/ai-foundations-juzjs) 进行指导练习。

<a id="bring-the-right-context-into-chatgpt"></a>

## 将正确的上下文带入 ChatGPT

为 ChatGPT 提供与任务相关的信息、工具和说明。您不需要提供所有内容，包括改变良好结果外观的上下文。

<a id="keep-related-work-in-a-project"></a>

### 将相关工作保留在项目中

项目可帮助您围绕主题、目标或正在进行的工作来组织 ChatGPT。当工作随着时间的推移继续进行或依赖于相同的上下文时，将相关的聊天、文件和说明保留在一个项目中。 [了解有关项目的更多信息。](projects.zh-CN.md)

<a id="attach-files"></a>

### 附加文件

您可以上传或附加文档、演示文稿、电子表格、PDF 文件、图像和数据导出。当您希望 ChatGPT 实现以下目的时，请使用它们：

- 总结或比较它们。
- 寻找模式或不一致之处。
- 提取、清理或重组信息。
- 使用它们作为新文件的源材料。

当ChatGPT创建文件时，打开预览并检查其内容。然后您可以要求更改而无需重新开始。了解有关 [处理文件](artifacts-viewer.zh-CN.md) 的更多信息。

<a id="connect-tools-with-plugins"></a>

### 将工具与插件连接起来

插件可以将 ChatGPT 连接到您用于工作的工具和信息，例如 Google Drive、SharePoint、Salesforce 或 Kong。当任务依赖于聊天之外的信息、另一个系统中的操作或可重复的工作流程时，请使用它们。



> 插图：ChatGPT 插件目录显示连接的工具，例如 Google Drive、Slack 和 SharePoint。



插件的可用性取决于您的计划、工作区设置和插件本身。了解有关 [技能和插件](skills-and-plugins.zh-CN.md) 的更多信息。

<a id="share-a-read-only-snapshot-of-a-codex-thread"></a>

## 共享 Codex 线程的只读快照

在所有 Codex 计划上，您可以在适用于 macOS 的 ChatGPT 桌面应用程序中创建本地 Codex 线程的只读快照。快照不会让其他人访问您的项目或计算机。

分享之前，请检查谁可以打开链接：

- **个人账户：** 知道链接的任何人都可以打开快照。
- **工作区帐户：** 只有创建快照的工作区中经过身份验证的成员才能打开它。您可以允许该工作区中的每个人或限制受邀人员和组的访问权限。工作区管理员可以关闭工作区共享链接。

1. 打开线程并选择 **分享**。您还可以在斜杠命令可用的情况下使用 `/share`。
2. 对于工作区帐户，请使用 **谁有权访问** 选择工作区中的每个人或 **仅受邀个人和团体**。对于仅限受邀者的访问，请通过电子邮件添加现有工作区成员或选择工作区组。
3. 等待快照上传完成，然后选择 **复制链接**。打开对话框即可开始上传，但仅当您选择 **复制链接** 时，Codex 才会使用您选择的受众和收件人发布快照。
4. 打开复制的链接并查看共享视图，然后再将其发送给任何人。

快照会捕获您共享时可用的受支持的线程内容。后续消息和更改不会更新现有快照。

共享快照可以包括用户可见的消息、推理摘要、图像附件、智能体查看或生成的图像以及文件更改（包括路径和差异）。它们不包括原始线程的工具调用、shell 命令或工具输入或输出。

Codex 在上传快照之前编辑已知的秘密模式。在发送链接之前查看共享视图，因为敏感内容（包括文件路径）可能会保留在消息、图像或差异中。

您无法从共享快照派生原始线程。您可以将快照作为附件导入并在新线程中引用它。

要查看或撤销共享链接，请打开 [ChatGPT数据控件](https://chatgpt.com/#settings/DataControls) 并选择 **共享链接**。

<a id="make-the-result-ready-to-use"></a>

## 使结果可供使用

将第一个结果视为可以检查、质疑和改进的草稿。完美的回复仍然可能不完整或错误，因此在使用或分享之前请先查看重要的细节。

**检查工作：**

- 验证重要的数字、名称、日期、引言和声明。
- 打开生成的文件并检查每个部分、选项卡、幻灯片或页面。
- 确认 ChatGPT 使用了正确且最新的源材料。
- 寻找缺失的信息和不受支持的假设。
- 当结果未达到目标时，要求进行重点修改。

然后让ChatGPT压测结果：

- “你为此使用了什么来源？”
- “引用每项主要主张的来源。”
- “你做了什么假设？”
- “您无法访问哪些信息？”
- “什么会改变你的推荐？”
- “根据原始文件检查这个结果。”

如果 ChatGPT 无法访问源或完成部分任务，请要求其明确说明。明确的差距比自信的猜测更容易解决。

法律、财务、医疗、安全和其他高风险决策需要适当的专家审查。使用ChatGPT来支持知情判断，而不是取代它。
