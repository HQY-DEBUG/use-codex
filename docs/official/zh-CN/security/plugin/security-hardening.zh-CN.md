# 安全加固建议

> 有关完整的文档索引，请参阅 [llms.txt](https://learn.chatgpt.com/llms.txt)。通过将 `.md` 附加到页面 URL 即可获得文档页面的 Markdown 版本。

使用 `$codex-security:propose-security-hardening` 将安全证据集合转化为结构或架构强化选项。该工作流程可以分析完整的 Codex Security 扫描，或从提供的调查结果、披露报告、事件审查、评估文件和源代码开始。

结果是一个设计组合，而不是补丁，并且不能证明它修复了漏洞。 Codex 仅在您选择一个选项并明确要求其进行更改后才更改仓库。

<a id="prepare-the-evidence"></a>

## 准备证据

提供工作流程：

- 扫描目录或结果和报告的明确集合。
- 目标源树和相关修订或快照（如果可用）。
- 支持调查结果的 PoC、痕迹、事件证据或评估材料。
- 性能、内存、兼容性、可靠性、操作、交付时间或变更范围的约束。

该工作流程使用证据来识别重复破坏的不变量、分散的控制、特权阻塞点、弱隔离边界和重复出现的补救模式。它还可以得出结论，局部修复比架构更改更合适。

<a id="run-the-workflow"></a>

## 运行工作流程

发送如下提示：

```text
使用 $codex-security:propose-security-hardening 分析 [扫描目录或查找针对 [ 源树和修订版本] 的路径 ]。通过工程权衡、前后图、迁移计划和实施移交来开发有证据支持的结构强化选项。不要修改仓库。
```

<a id="review-the-portfolio"></a>

## 审查投资组合

一个有用的投资组合应该：

- 将每个提议的变更与具体的发现、来源和威胁模型证据联系起来。
- 描述当前设计和新设计应保留的安全不变量。
- 比较不同的选项，包括残余风险、性能、可靠性、操作、兼容性和迁移成本。
- 仅当有证据支持、有明确的假设和开放性问题时才推荐一个选项。
- 包括推出、验证、回滚和实施指南。
- 将观察到的事实、推论和提议的设计属性分开。

在选择选项之前查看证据和权衡。架构图或设计建议不能取代对原始发现或已实施修复的验证。

<a id="use-hardening-guidance-from-a-scan"></a>

## 使用扫描的强化指导

您可以请求强化组合以进行标准扫描、深度扫描或更改扫描，并提供可报告的结果。 Codex 将投资组合写入 ​​`hardening/hardening.md`，将结构化分析写入 `hardening/hardening.json`，并在 `hardening/` 下支持建议或图表。扫描链接来自 `report.md` 的投资组合。

将完整扫描目录放在一起，以便这些链接仍然可用。要查看为投资组合提供信息的各个报告，请参阅 [撰写漏洞报告](vulnerability-reports.zh-CN.md)。
