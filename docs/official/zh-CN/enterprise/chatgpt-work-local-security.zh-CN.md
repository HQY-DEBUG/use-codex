<a id="chatgpt-work-local-security"></a>

# Work 本地安全

> 有关完整的文档索引，请参阅 [llms.txt](https://learn.chatgpt.com/llms.txt)。通过将 `.md` 附加到页面 URL 即可获得文档页面的 Markdown 版本。

ChatGPT Work 可以使用用户计算机上批准的文件、应用程序和浏览器会话来完成本地任务。访问权限取决于工作区权限、用户的现有帐户访问权限、操作系统权限、应用程序批准和支持的设备策略。

本地功能取决于支持的桌面应用程序、操作系统、工作区权利、角色权限、设备策略和产品部署。

<a id="security-at-a-glance"></a>

## 安全一目了然

- 本地任务通过 ChatGPT 桌面应用程序运行。在同一应用程序中打开托管云任务不会使该任务成为本地任务。

- 可用的本地和托管工作控件取决于工作区配置和部署。

- 文件访问、计算机使用、浏览器和连接的应用程序使用不同的权限和批准。

- 已登录公司系统的浏览器或应用程序可以公开该现有帐户的权限。

- 支持的托管设备策略可以限制本地功能，而无需替换工作区访问控制。

- 由所涵盖的 OpenAI 服务处理的商业、企业和教育工作区数据在传输和静态时均进行加密，默认情况下不用于训练 OpenAI 模型。

- 本地文件、任务上下文、浏览器数据、连接系统记录和审核事件可以遵循不同的存储和保留规则。

<a id="where-local-tasks-run"></a>

## 本地任务运行的地方

Work Local 通过用户计算机上的桌面应用程序访问批准的资源。 Work Cloud 在 OpenAI 管理的基础设施上运行，即使从同一桌面应用程序打开也是如此。

本地文件可以保留在设备上，但相关文件摘录、提示、屏幕截图、浏览器内容或工具结果可能会发送到 OpenAI 服务以完成任务。本地执行并不意味着离线或仅设备模型推理。

<a id="files-and-device-access"></a>

## 文件和设备访问

本地任务可以使用用户提供或可用的信息，包括支持的文件、应用程序内容、浏览器会话和授权的连接系统。访问权限取决于用户的现有权限和管理该特定功能的控制。

授予本地工作访问权限不会自动批准每个应用程序、授予管理员权限或绕过用于访问另一个系统的帐户的权限。批准的共享连接可以具有与用户个人帐户不同的权限。

<a id="computer-use-and-application-approvals"></a>

## 计算机使用和应用程序批准

仅当该功能可用、授予所需的操作系统权限并且用户授权该应用程序时，[电脑使用](../computer-use.zh-CN.md) 才能与支持的桌面应用程序交互。根据可用选项，批准可以应用于当前会话或未来任务。

在 macOS 上，屏幕录制允许计算机使用查看应用程序内容，而辅助功能允许其单击、键入和导航。支持的 macOS 任务可以在后台运行。在 Windows 上，“计算机使用”在活动的可见桌面上运行，并且当用户继续使用同一会话时无法在后台运行。

用户可以随时停止任务。计算机使用无法批准操作系统安全提示、以管理员身份进行身份验证或自动执行终端应用程序或 ChatGPT 本身。

<a id="locked-devices"></a>

### 锁定的设备

支持的 macOS 配置可以选择允许在 Mac 锁定时继续批准的计算机使用任务。可用性取决于应用程序版本、功能推出、适用要求和远程控制资格。

管理员可以通过支持的托管配置禁用锁定设备操作。 Windows 计算机使用需要一个活动的、未锁定的桌面； macOS 锁定使用行为未建立等效的 Windows 支持。

<a id="browser-sessions-and-existing-sign-ins"></a>

## 浏览器会话和现有登录

Work Local 不会自动获得对每个浏览器或公司帐户的访问权限。访问权限取决于所使用的浏览器、登录帐户以及该浏览器体验所需的批准。

| 浏览器路径 | 会话和安全边界 |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [桌面应用内浏览器](../browser.zh-CN.md) | 使用与用户常规浏览器不同的浏览器配置文件。用户可以在该配置文件中登录，并且支持的网站访问可能需要批准。内置浏览器无法自动上传文件。              |
| [Chrome 扩展程序](../chrome-extension.zh-CN.md) | 当扩展程序和网站访问获得批准时，可以与现有浏览器选项卡和帐户进行交互。用户可以批准网站一次或允许将来访问；浏览器历史记录和本地文件访问需要单独审查。 |
| 计算机使用操作浏览器 | 使用批准为桌面应用程序的浏览器，包括已登录到该浏览器的帐户。操作系统权限、应用程序审批和现有帐户的权限仍然适用。               |

网站批准选项和敏感操作确认因浏览器体验而异。允许所有站点会减少未来的批准提示，因此用户应在启用之前检查该选择。

托管云浏览器与用户的本地浏览器分离，并且不会自动继承其现有登录。支持的云工作流程可以请求单独的、用户授权的登录。

<a id="apps-plugins-and-connected-accounts"></a>

## 应用程序、插件和连接的帐户

连接的应用程序可以提供对另一个系统中的信息或操作的访问。插件可以使用应用程序作为底层工具。使插件可用并不会自动启用所需的应用程序、授权帐户或允许所有操作。

插件和应用程序的可用性取决于工作区规划和配置。 [ChatGPT Work概述](chatgpt-work-overview.zh-CN.md) 将插件及其底层应用程序描述为企业和教育工作区默认关闭，业务工作区默认打开。验证相关工作区和产品体验的实际设置。

在任务使用连接的系统之前，请确认工作区允许应用程序和任何所需的插件，连接已获得授权，并且连接的帐户可以访问请求的信息或操作。只读设置、允许的操作和确认要求因集成而异。

仅桌面插件、本地工具和其他本地提供的功能可以遵循不同的安装或批准路径。不要假设每个本地工具都使用相同的行政审批流程。

<a id="personal-and-shared-connections"></a>

### 个人和共享连接

个人连接使用连接用户在源系统中的权限。共享或智能体拥有的连接使用连接帐户的权限，该权限可能比用户自己的访问权限更广泛。

将共享帐户限制为必要的数据和操作，限制可以使用它们的人员，并应用支持的操作或确认控制。连接系统中的记录仍受该系统的权限和保留策略的约束。

<a id="administrator-access-and-managed-device-policies"></a>

## 管理员访问和受管设备策略

查看 **工作区设置** > **权限和角色** 中可用的工作控件。本地工作和托管工作是否显示为不同的权限取决于工作区配置和部署。如需更多指导，请参阅 [工作管理员常见问题解答](work-admin-faq.zh-CN.md)。

仅启用为每个用户或组批准的执行环境，并在更改后验证有效访问。

工作区权限决定谁可以使用工作。管理员还可以通过 `requirements.toml` 中定义的强制要求来限制支持的桌面功能。根据部署的不同，这些要求可以通过工作区管理的配置、系统级配置文件或支持的 macOS 移动设备管理工具来满足。

强制要求不能被个人用户覆盖。相比之下，托管默认设置建立了用户可以更改的初始设置。两者都不会取代工作区角色或操作系统权限。

| 托管设置 | 安全目的 |
| ----------------------------------------------------- | ---------------------------------------------------------------------------- |
| `features.computer_use = false` | 禁用支持的计算机使用功能。                                 |
| `allow_appshots = false` | 防止支持的 Appshot 捕获。                                           |
| `features.in_app_browser = false` | 禁用桌面应用程序的内置浏览器。                                  |
| `features.browser_use = false` | 禁用支持的浏览器自动化；单独查看其他浏览器路径。 |
| `features.apps = false` 或 `features.plugins = false` | 限制支持的连接的应用程序或插件。                        |
| `computer_use.allow_locked_computer_use = false` | 在 Mac 锁定时防止支持的计算机使用。                        |

可用的设置和交付方法取决于客户端、操作系统、工作区和部署配置。验证对代表性受管设备的限制。有关支持的策略设置、配置示例和 MDM 设置说明，请参阅 [受管配置](managed-configuration.zh-CN.md)。

<a id="local-networking-and-private-resources"></a>

## 本地网络和私有资源

任务可以通过设备浏览器、批准的桌面应用程序或连接的应用程序等路径访问公司信息。现有设备、代理、VPN、源系统和端点控制可能以不同的方式应用于每个路径。

访问企业 VPN 不会自动授权每个工具使用每个内部资源。同样，云工作浏览器或云网络控制并不是对本地设备网络的普遍限制。查看工作流所需的实际连接、身份、目标和操作。

<a id="data-handling-and-retention"></a>

## 数据处理和保留

将组织的端点、文件访问、代理和数据丢失防护控制应用于特定设备和工作流程。在处理之前确认这些控制措施是否可以阻止敏感信息进入任务。审核日志和合规性导出有助于监控和调查，但本身不会阻止处理。

存储和保留取决于信息类别及其保存位置。

| 信息类别 | 评论内容 |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 本地对话记录 | 桌面体验如何存储、删除、备份或共享本地记录。不要假设托管对话保留设置适用于每个本地工件。 |
| 本地文件和生成的输出 | 设备存储、端点策略、用户授权的上传、外部共享以及任何单独保存的副本。                                                       |
| 提示、文件摘录和应用程序上下文 | 提供给模型或服务的内容、适用的工作区术语以及工作流的实际数据流。                                                           |
| 语音和应用程序快照 | 麦克风输入、最前面的窗口屏幕截图、可访问的应用程序文本、本地会话存储以及作为任务上下文发送的任何内容。                          |
| 浏览器数据 | 涉及的浏览器配置文件、现有登录、浏览历史记录、下载、网站批准以及任何单独存储的任务内容。                           |
| 连接系统记录 | 源系统权限和保留、连接帐户身份以及单独保存到对话或其他目标的任何信息。              |
| 合规性和活动记录 | 哪些工作本地事件可用于工作区、支持的集成以及接收系统的保留策略。                                   |

对于受支持的 Business、Enterprise 和 Edu 工作区，由涵盖的 OpenAI 服务处理的业务数据在传输和静态时都会进行加密，并且默认情况下不用于训练或改进 OpenAI 模型。这些保护并不意味着 OpenAI 可以管理每个设备文件、第三方应用程序、浏览器配置文件或源系统记录。

在未确认其适用于特定数据类别的情况下，请勿将托管对话、临时上传或合规日志保留期应用于本地记录。

<a id="audit-and-compliance-visibility"></a>

## 审计和合规可见性

可用的报告取决于工作区计划、产品体验、事件、连接的应用程序和部署的配置。在依赖工作区导出进行事件响应或监管审查之前，请验证工作本地覆盖范围。

确定相关系统是否记录任务标识、支持的提示和响应、连接的应用程序调用、浏览器批准、应用程序操作、本地文件活动或端点事件。源系统和设备记录可以提供与 ChatGPT 工作区记录不同的可见性。

OpenAI 不会存储通过扩展程序执行的 Chrome 操作的单独完整记录。不要假设每个本地文件操作、屏幕截图、浏览器操作、批准或外部更新都出现在合规性 API 中。

<a id="start-with-one-approved-task"></a>

## 从一项批准的任务开始

从托管设备上的一小组开始，然后选择一项已批准的任务，例如比较选定的财务工作簿。确认每个用户的工作访问权限，并仅提供任务所需的文件、应用程序、浏览器会话或连接的帐户。

检查批准的操作是否有效、受限操作是否被阻止以及可用记录是否满足您的监控需求。在扩展访问权限之前，让用户查看结果和任何外部更改。
