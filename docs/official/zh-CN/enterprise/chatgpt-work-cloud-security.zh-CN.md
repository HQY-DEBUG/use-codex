# Work 云端安全

> 有关完整的文档索引，请参阅 [llms.txt](https://learn.chatgpt.com/llms.txt)。通过将 `.md` 附加到页面 URL 即可获得文档页面的 Markdown 版本。

ChatGPT Work 是您现有 ChatGPT 工作区的一部分，并遵循其适用的隐私、安全和数据处理策略。对于商业、企业和教育工作区，现有保护包括传输中和静态加密，并且 OpenAI 默认情况下不使用业务数据来训练其模型。

Work Cloud 还引入了托管任务执行和可选工具，可以访问连接的系统或采取授权操作。查看您的组织启用的功能的权限、保留设置和可用审核记录。

功能和控制取决于工作区规划、部署、配置和连接集成。对于更广泛的执行模型，请参阅 [ChatGPT Work概述](chatgpt-work-overview.zh-CN.md)。

<a id="security-at-a-glance"></a>

## 安全一目了然

- 云中的任务在 OpenAI 管理的基础设施上运行，而不是在用户的设备上运行。
- 云任务不会继承该设备的本地文件、桌面应用程序、浏览器会话或专用网络访问权限。
- 连接的应用程序使用授权帐户的权限，该帐户可以是个人、共享或智能体拥有的帐户。
- 工作区和特定功能的控件管理工作访问、本地执行、云浏览、连接的应用程序以及代码或 shell 网络。
- Business、Enterprise 和 Edu 工作区数据在传输和静态时均进行加密，默认情况下不用于训练 OpenAI 模型。
- 保留和审核可见性取决于数据类别、存储位置、事件和适用的产品配置。

<a id="where-cloud-tasks-run"></a>

## 云任务运行的位置

人们可以从支持的 ChatGPT Web、移动或桌面体验启动云任务。网络工作和移动设备在云中运行。当相应的权限可用并启用时，桌面应用程序可以运行云或本地任务。

用户的设备位于组织自己的 IT 管理的信任边界内，位于 OpenAI 操作系统之外。从桌面应用程序启动云任务不会让任务直接访问用户的计算机。无论用于启动它的使用界面如何，执行都会保留在 OpenAI 管理的环境中。

Work Cloud 使用 Codex 任务执行工具。 Work 和 Codex 共享核心执行和隔离机制，但它们的可用工具、权限和管理控制并不相同。客户控制工作区访问、批准的连接以及有意提供给任务的信息； OpenAI 管理托管执行环境。

Work Cloud 在 OpenAI 管理的共享基础设施上运行。在当前支持的执行路径中，任务在虚拟机支持的沙箱中运行，其执行状态与工作区中经过身份验证的帐户用户相关联。工作可以跨任务重用环境或替换它，同时保留合格的状态。这并不意味着每个任务都会收到一个新容器，或者每个客户都有一个专用的物理主机。客户不提供、托管或管理 Work Cloud 容器。

<a id="what-a-cloud-task-can-access"></a>

## 云任务可以访问什么

云任务可以使用通过授权路径提供的信息：

- 一个人进入对话的信息。
- 有意上传、从库附加或通过项目提供的文件。
- 通过启用的应用程序和授权帐户连接检索内容。
- 通过启用的云浏览器或其他允许的网络功能访问网站内容，并遵守适用的访问控制。

云任务不会直接继承对本地文件、已安装应用程序或用户浏览器会话的访问权限。设备对公司 VPN、内部网站或专用网络的访问不会授予云任务该访问权限。

授权连接可以通过其自己的访问路径提供来自内部系统的信息。该连接不会让云任务不受限制地访问员工的设备或网络。

<a id="apps-plugins-and-connected-accounts"></a>

## 应用程序、插件和连接的帐户

应用程序可以让工作部门访问另一个系统中的信息或操作。插件可以使用应用程序作为其底层工具之一。使插件可用不会自动启用底层应用程序、授权帐户或批准集成可以执行的每个操作。

直接或通过插件使用连接的应用程序的任务只能在以下情况下继续：

- 工作区启用应用程序和任何需要它的插件。
- 此人具有必要的工作区或角色访问权限。
- 连接使用授权的个人、共享或智能体拥有的帐户。
- 连接的帐户、批准的范围和可用的应用程序操作设置允许请求的信息或操作。

对于支持 **动作控制** 的应用程序，管理员可以允许只读操作、所有操作或自定义操作集。 **应用程序权限** 控制 ChatGPT 何时要求确认使用应用程序。根据应用程序和工作区，选项可能包括 **总是问**、**任何变更**、**重要行动** 和 **从不问**。使用 **任何变更**，支持的读取可以在没有提示的情况下继续进行，而更改则需要确认。

当配置的策略允许时，授权写入可以在没有提示的情况下运行。这不会扩展应用程序允许的操作、工作区访问权限或连接帐户的权限。 ChatGPT仍然可以阻止一些高风险行为。

确认插件和每个底层应用程序在工作区中可用。将角色访问、连接帐户授权和操作权限视为不同的决策。参见 [插件控件](apps-and-connectors.zh-CN.md)。

<a id="personal-and-shared-connections"></a>

### 个人和共享连接

个人连接使用连接的员工在源系统中的权限。共享或智能体拥有的连接使用其连接帐户的权限。该帐户可能会访问请求者无法使用个人帐户访问的信息或执行操作。

在启用共享连接之前，请限制帐户的权限和范围，选择谁可以使用它，并查看它可以执行的操作。参见 [工作区智能体连接和权限](https://help.openai.com/en/articles/20001143-chatgpt-workspace-agents-for-enterprise-and-business)。

从连接的应用程序检索的内容不会自动保存为库文件。如果内容稍后保存到对话、项目、库或同步索引，则该副本将遵循其保存位置的规则。

<a id="cloud-browser-and-network-access"></a>

## 云浏览器和网络访问

云浏览器、网络搜索、连接的应用程序以及代码或 shell 网络是独立的功能。限制其中一项并不会自动禁用其他项。

<a id="cloud-browser"></a>

### 云浏览器

云浏览器是工作任务可用于与网站交互的托管工具。在网络浏览器或桌面应用程序中打开 ChatGPT 不会启用云浏览；云任务可以在没有它的情况下运行。

托管浏览器不会继承用户的本地浏览器配置文件、打开的选项卡、现有登录、保存的密码、密码管理器或浏览历史记录。在支持的情况下，用户可以通过安全托管登录流程单独登录。这不会授予对其本地浏览器会话的访问权限。

支持的网站交互可以包括公共表单，并且可以将来自授权应用程序的信息与网站任务结合起来。如果可用，网站权限包括 **总是问**、**自动批准** 和 **始终允许**。 **自动批准** 应用自动化风险检查； **始终允许** 删除交互式网站访问审核。既不授予新的应用程序权限，也不批准网站上的每项操作。后续行动仍可能需要单独确认。

对于要在企业工作区中使用云浏览器的工作任务，管理员必须同时启用工作访问和云浏览器访问。参见 [在ChatGPT中使用云浏览器](https://help.openai.com/en/articles/20001280-using-cloud-browser-in-chatgpt)。

<a id="code-and-shell-networking"></a>

### 代码和 shell 网络

代码或 shell 执行的公共互联网访问遵循其自己的网络策略。当公共互联网访问关闭时，ChatGPT Work 所需的网络目标可以通过托管目标白名单保持可达。

允许列表管理网络目标，而不是 shell 命令。禁用代码或 shell 执行的公共互联网访问本身并不会禁用云浏览器、网络搜索或连接的应用程序。对网络设置的更改将在当前代码运行或 shell 命令完成并且执行环境刷新后应用。

参见 [代码和 shell 沙箱](../sandboxing.zh-CN.md)。

<a id="data-handling-and-retention"></a>

## 数据处理和保留

Work Cloud 遵循上述适用的 ChatGPT 工作区隐私和安全保护。参见 [企业隐私](https://openai.com/enterprise-privacy/)。

与云任务关联的信息不遵循一个通用保留计划：

| 数据类别 | 保留和删除行为 |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 工作对话 | 遵循工作区对话保留设置。已删除的聊天记录通常会在 30 天内永久删除，但须遵守已公布的安全、法律和去识别化例外情况。                                                                                |
| 托管执行状态和快照 | 遵循与对话和文件不同的生命周期。对执行状态的访问仅限于帐户用户，工作区会话保留设置会通知符合条件的存储快照。结束任务或删除聊天不会立即清除所有相关工件。 |
| 保存到库的文件 | 上传或生成的文件遵循适用的库和工作区保留规则。删除对话不会删除保存到库中的文件。                                                                                                                                      |
| 项目文件 | 根据适用的删除规则，在删除或项目被删除之前保持与其项目关联。                                                                                                                                                                       |
| 启用时保存的内存 | 遵循单独的内存控制。删除对话并不一定会删除现有的已保存记忆。                                                                                                                                                                             |
| 临时上传 | 库外符合条件的临时企业上传可能会在 48 小时后过期，除非应用其他适用的保留设置。                                                                                                                                                      |
| 连接的应用程序内容 | 源系统记录遵循该系统的策略。保存到对话、项目、库或同步索引的副本遵循其保存位置的规则。                                                                                                                         |
| 云浏览器数据 | 托管浏览器数据与本地浏览器数据分开。用户可以通过适用的设置删除保存的云浏览器 cookie。                                                                                                                                                    |
| 合规记录 | 合规日志平台记录的有效期为 30 天。导出的副本遵循接收系统的保留策略。                                                                                                                                                               |

删除对话、删除库文件或节省的内存、断开应用程序连接以及清除托管浏览器数据是单独的操作。检查相关的存储位置，而不是假设一个操作会删除每个副本。参见 [聊天和文件保留策略](https://help.openai.com/en/articles/8983778-chat-and-file-retention-policies-in-chatgpt)。

保留适当的对话和执行上下文可以帮助 Work 恢复中断的任务、参考之前的步骤并产生更一致的结果。较短的保留或删除时间可能会降低连续性，因此请选择平衡安全要求与工作流程实用性的设置。

符合条件的企业和教育工作区可以使用企业密钥管理来存储支持的内容，包括需要客户管理的加密时支持的托管执行快照。覆盖范围因数据类别和部署而异。轮换密钥不会删除现有数据，也不会拒绝对早期加密内容的访问。撤销或禁用密钥访问是一项单独的操作，可能会中断支持的工作流程。两者都不能取代保留或删除策略。

数据驻留和推理驻留仅适用于符合条件的内容和支持的工作负载，具体取决于组织的协议、区域和配置。连接的应用程序、外部提供商以及某些处理或同步索引可以遵循单独的位置规则。验证对产品、集成和区域的支持。参见 [数据驻留和推理驻留](https://help.openai.com/en/articles/9903489-data-residency-and-inference-residency-for-chatgpt)。

OpenAI API [零数据保留](https://developers.openai.com/api/docs/guides/your-data#zero-data-retention) 是特定于 API 的控件，不定义 ChatGPT Work 的保留。

<a id="administrator-access-controls"></a>

## 管理员访问控制

查看适用于云任务每个部分的控制：

- **云工作和本地工作：** 在独立控件可用的情况下，管理云和本地 在 **工作区设置** > **权限和角色** 中作为不同控件工作。在其他工作区中，本地 Work 可以与 Codex Local 共享一个控件。
- **应用程序和插件：** 选择哪些集成可用以及哪些人员或角色可以使用它们。
- **关联帐户操作：** 查看帐户权限、应用程序范围以及可用的操作或确认控制。
- **浏览器和网络：** 独立评估云浏览器访问和代码或外壳公网访问。

仅对批准的用户或组启用 **工作云**。如果有单独的 **工作云** 和 **本地工作** 控件可用，请针对预期角色启用 **工作云** 并禁用 **本地工作**，以允许云工作而无需本地执行。如果本地工作和 Codex 共享一个控件，请在禁用本地执行之前检查对两者的影响。这些控件不会阻止授权人员故意将文件上传到云任务。

对于具有 **默认**、**开** 和 **关闭** 状态的受支持角色权限，**默认** 继承工作区设置，**开** 授予访问权限，**关闭** 通过该角色删除访问权限。如果用户具有多个自定义角色，另一个角色仍然可以授予访问权限。某些工作和插件设置使用不同的两种状态控件。验证所有分配角色的有效访问权限。参见 [基于角色的访问控制](https://help.openai.com/en/articles/11750701-rbac)。

如果可用，**工作云** 权限适用于受支持的 Web、移动和桌面体验。它不会独立选择哪些使用界面可以运行云任务。如果部署必须排除特定使用界面，请考虑设备管理或其他访问控制。

<a id="audit-and-compliance-visibility"></a>

## 审计和合规可见性

对于符合条件的企业和教育工作区，合规性日志平台可以包括支持的工作提示和响应。连接的应用程序调用具有单独的日志，可用的源系统审核记录因集成而异。支持的合规性端点可以提供对合格库文件的访问。

覆盖范围取决于事件及其发生的系统。不要假设每个 shell 命令、浏览器交互、应用程序调用、文件操作或批准都出现在客户可见的合规性导出中。

端点监控可以观察受管设备上的 ChatGPT 客户端或网络流量，但无法检查托管执行环境内的操作。请改用支持的工作、合规性和连接系统记录。

审查当前的合规事件覆盖范围以及工作区报告、连接系统审核日志以及接收导出记录的系统的保留策略。请参阅 [OpenAI 合规平台](https://help.openai.com/en/articles/9261474-compliance-api-for-chatgpt-enterprise-edu-and-chatgpt-for-teachers)。

<a id="start-with-a-small-pilot"></a>

## 从一个小飞行员开始

为小组选择一项实际任务。例如，安全团队可以将批准的供应商咨询与授权库存进行比较，并在决定做什么之前审查暴露评估草案。如果云浏览或连接的应用程序不可用，请直接提供咨询和批准的库存摘录。

仅启用任务所需的访问权限。确认连接帐户权限、保留设置、可用审核记录以及在扩展访问权限之前应在何处查看结果。有关部署规划，请参阅 [管理员推出指南](admin-setup.zh-CN.md)。
