<a id="0124-september-9-2026"></a>

## 0.1.24（2026 年 9 月 9 日）

<a id="check-daybreak-access-from-the-plugin"></a>

### 检查插件的 Daybreak 访问权限

- 在使用 ChatGPT 登录的桌面和 CLI 会话中扫描之前检查 Daybreak 访问权限，无需连接单独的 Codex Security Access 应用程序。
- 在未授予访问权限时显示注册链接，在无法验证访问权限时显示警告。仅使用 API 密钥的会话无法验证帐户访问权限。
- 在出现建议后继续扫描，包括在访问不可用或检查失败时。该通报不授予访问权限或控制扫描是否运行。

<a id="verify-security-fixes-when-requested"></a>

### 根据要求验证安全修复

- 仅当您明确请求验证安全修复程序时才运行 `$codex-security:verify-fix`。
- 将普通的修复实施、代码审查和测试请求保留在现有工作流程中，而不是自动切换到验证结果格式。

<a id="0123-september-8-2026"></a>

## 0.1.23（2026年9月8日）

<a id="assess-the-risk-of-a-proposed-patch"></a>

### 评估拟议补丁的风险

- 使用 `$codex-security:assess-patch-risk` 根据确切的修订和源证据审查提议的更改。
- 与回归保护分开评估影响、可能性和恢复难度，并确定影响建议的证据差距。
- 收到合并、修改或不做任何更改的咨询建议。评估不会合并代码或替换仓库批准规则。

<a id="recover-retained-results-from-failed-scans"></a>

### 从失败的扫描中恢复保留的结果

- 当您请求时，从选定的失败扫描中恢复有效的已保存结果，而无需重复扫描。
- 浏览保存的扫描和结果，而无需自动恢复每个失败的扫描。恢复会保留失败的结果，并且不可用于运行、已完成或取消的扫描。
- 当工作人员重复使用候选标识符时保留明显的发现，并在恢复过程中保留有效的证据和根本原因详细信息。

<a id="make-scan-setup-and-reports-clearer"></a>

### 使扫描设置和报告更清晰

- 在标准和变更扫描中查看各个准备情况检查及其阻止或警告详细信息。
- 在您决定如何解决设置问题时，请保留扫描以供继续使用。交互式会话中的持久配置更改仍然需要您的批准。
- 查看深度扫描报告中配置的包含和排除路径。
- 将上下文更新范围保持在选定的扫描范围内，而不替换已保存的工作区默认值。

<a id="improve-startup-and-github-triage"></a>

### 改进启动和 GitHub 分类

- 允许插件的工具服务器最多启动两分钟，并将 OpenAI API 密钥身份验证传递给深度扫描工作人员。
- 导入分类结果时遵循明确选择的 GitHub 连接器，并在切换到其他连接或帐户之前询问。

<a id="0122-august-25-2026"></a>

## 0.1.22（2026年8月25日）

<a id="verify-existing-security-fixes"></a>

### 验证现有的安全修复

- 使用 `$codex-security:verify-fix` 检查现有补丁是否可以解决报告的安全问题，而无需更改仓库文件或问题跟踪器。
- 接收每个发现的 `fixed`、`still_vulnerable` 或 `inconclusive` 结果，以及支持证据和验证限制。
- 在查找修复工作流程中添加修补前的调查和修补后的审查。

<a id="preserve-findings-when-scans-stop"></a>

### 扫描停止时保留结果

- 随着深度扫描工作人员取得进展，保存结果和待定候选人。
- 当以后的结果合并忽略或失败时，保留已接受的工作人员发现。
- 保留失败、取消或中断扫描的有效结果，同时保留其不成功结果和不完整的覆盖范围。
- 将提供的扫描提示携带到深度扫描工作线程中，并保留父会话中支持的文件系统拒绝规则。

<a id="improve-windows-and-filesystem-compatibility"></a>

### 提高 Windows 和文件系统兼容性

- 匹配扫描历史记录中的等效 Windows 路径并从预期位置加载 Windows 系统配置。
- 阻止 Windows 解释不明确的扫描工件路径。
- 将扫描结果保存在不支持硬链接的文件系统上。
- 在 Python 3.10 上一致地读取 UTC 扫描时间戳。

<a id="0121-august-21-2026"></a>

## 0.1.21（2026年8月21日）

<a id="install-and-start-the-plugin-more-reliably"></a>

### 更可靠地安装和启动插件

- 安装插件无需可选的 Codex Security Access 应用程序。托管访问检查仍然是建议性的。
- 启动插件时使用 Codex 捆绑的 Node.js 运行时，包括在 Windows 安装中打包的可执行文件无法直接运行。
- 在 Windows 上以 UTF-8 形式读取 Git 元数据。

<a id="preserve-finding-details-and-improve-sarif-exports"></a>

### 保留发现细节并改进 SARIF 导出

- 在保存的结果、报告和安全工作台中保持验证、攻击路径证据和根本原因详细信息一致。
- 导出 GitHub 代码扫描的可读规则名称、修复指南、CWE 标签和安全严重性，同时保留查找到的身份、指纹和源位置。

<a id="0120-august-17-2026"></a>

## 0.1.20（2026年8月17日）

<a id="run-deep-scans-as-complete-independent-audits"></a>

### 运行深度扫描作为完整的独立审核

- 通过与标准扫描相同的端到端审核来运行每个深度扫描工作人员，包括威胁建模、验证、攻击路径分析和覆盖率报告。
- 将已完成的工作人员报告合并到一次扫描中，同时保留配置的时间限制、部分覆盖、重新启动恢复和取消。
- 默认情况下使用四个并发工作线程，在四次连续完成的扫描没有添加新发现后停止，并将深度扫描限制为 40 个工作线程运行。现有的 `workers = "auto"` 设置现在解析为四个工作人员。参见 [配置深度扫描运行时](deep-scans.zh-CN.md#configure-deep-scan-runtime)。
- 恢复完成源代码审查但丢失最终草案的工作人员，而不是重复完整的审核。

<a id="check-trusted-access-for-cyber-before-hosted-scans"></a>

### 在托管扫描之前检查网络的可信访问

- 在公开 Codex Security Access 应用程序的 Codex 主机中，在开始标准扫描、更改扫描和深度扫描之前检查可信访问状态。
- 当受保护的扫描输出可能不可用时，会看到显着的警告；在未授予访问权限时，会显示注册链接。
- 当检查无法验证可信访问状态或未授予访问权限时继续扫描；该通报不控制扫描是否运行。
- 公共 CLI 和 SDK 包不会在 `0.1.20` 中运行此通报。

<a id="run-deep-scans-in-more-environments"></a>

### 在更多环境中运行深度扫描

- 从打包的 CLI 和 SDK 安装启动深度扫描工作程序，包括没有全局 `codex` 可执行文件的 Windows 安装。
- 将独立的 CLI 和 SDK 深度扫描设置与其他正在运行的扫描隔离。
- 在嵌套深度扫描工作人员中保留非交互式审批设置。

<a id="preserve-scan-results-through-more-failures"></a>

### 通过更多失败保留扫描结果

- 在重新启动、存档和切换恢复路径中保留更多已保存的扫描和已完成的工作结果。
- 从旧的或不完整的扫描数据中恢复有效的结果。
- 当独立覆盖报告重叠时完成扫描。
- 在当前和旧的提供商响应中正确报告令牌使用总数中的缓存输入。

<a id="0119-august-13-2026"></a>

## 0.1.19（2026年8月13日）

<a id="set-a-time-limit-for-deep-scans"></a>

### 设置深度扫描的时间限制

- 将 `[deep_scan].max_time_hours` 设置为最长 96 小时的正持续时间。您可以使用小数小时。
- 在截止日期到期时保留已完成的发现结果，然后继续验证和报告。
- 如果在截止日期之前没有完成源审核，则将报告标记为部分。

<a id="improve-scan-reliability"></a>

### 提高扫描可靠性

- 当工作线程停止或减速器重试时，保留已完成的发现工作。
- 读取更大的源文件并生成报告，没有以前的固定大小限制。
- 从所选修订中读取已提交的更改并在 Windows 上保留仓库相对路径。
- 将 OpenRouter 和 Fireworks 凭据传递给深度扫描工作人员。

<a id="0118-august-7-2026"></a>

## 0.1.18（2026年8月7日）

<a id="use-amazon-bedrock-for-security-scans"></a>

### 使用 Amazon Bedrock 进行安全扫描

- 使用 Amazon Bedrock 不记名令牌和 AWS 配置文件、区域设置、Web 身份或容器凭证运行扫描。
- 让 AWS 身份验证可供委派的深度扫描工作人员使用。

<a id="run-standard-scans-with-less-coordination"></a>

### 以较少的协调运行标准扫描

- 使用更简单的工作流程进行标准仓库和范围路径扫描。
- 保留嵌套的 `SECURITY.md` 指导、精确的扫描范围、进度更新和最终扫描报告。

<a id="start-and-complete-scans-more-reliably"></a>

### 更可靠地开始和完成扫描

- 给予提示启动扫描长达五分钟的时间来初始化大型仓库，而不是在 30 秒后超时。
- 当主机强制执行工具名称长度限制时，完成标准扫描和深度扫描。

<a id="keep-remediation-available-after-filesystem-changes"></a>

### 文件系统更改后保持修复可用

- 文件系统重新挂载更改其设备标识符后，修复已完成扫描的结果。
- 在应用修复之前，继续要求原始签出和 Git 修订。

<a id="0117-august-5-2026"></a>

## 0.1.17（2026年8月5日）

<a id="follow-scan-progress-as-it-happens"></a>

### 跟踪扫描进度

- 从单个实时进度视图跟踪当前扫描阶段、已用时间、活动工作人员、已审阅的文件和令牌使用情况。
- 文件完成时查看仓库审核进度更新，而不是等待扫描完成。

<a id="resume-interrupted-deep-scans"></a>

### 恢复中断的深度扫描

- 在协调器重新启动后继续进行正在进行的深度扫描，而无需重复已完成的文件审查。
- 跨应用程序更新或中断的扫描会话保留已完成的发现结果、扫描所有权和待处理工作。

<a id="start-and-complete-scans-with-less-overhead"></a>

### 以更少的开销开始和完成扫描

- 直接在本机工作流程中启动标准扫描、更改扫描和深度扫描，无需打开已停用的嵌入式扫描小部件。
- 重复使用已完成的扫描摘要，无需重新加载每个结果，除非您请求完整的结构化结果。

<a id="0116-august-4-2026"></a>

## 0.1.16（2026年8月4日）

<a id="track-measured-scan-usage"></a>

### 跟踪测量的扫描使用情况

- 查看主扫描及其委派工作人员的总、输入、缓存输入和输出令牌使用情况。
- 区分完整、部分和不可用的测量，而不是将缺失的使用显示为零。

<a id="run-deeper-scans-with-consistent-results"></a>

### 运行更深入的扫描并获得一致的结果

- 对标准扫描和深度扫描使用相同的威胁建模、发现、验证、攻击路径分析和报告阶段。
- 从 CLI 或 SDK 配置深度扫描工作线程、每个工作线程委派、饱和度和发现限制。
- 使用模型支持的工作运行时运行深度扫描并恢复旧的扫描状态，而不会丢失现有的扫描历史记录。
- 生成变更和深度扫描的主要报告，无需单独编写漏洞或强化建议。

<a id="keep-scan-guidance-and-repository-targets-accurate"></a>

### 保持扫描指导和仓库目标准确

- 在主动扫描期间更新安全指南，并将其带入后续阶段并委派深度扫描工作人员。
- 保留仓库 URL、拉取请求引用和更长的安全上下文，而不允许您未请求的网络访问。
- 当仓库或扫描目标在执行期间发生更改时，扫描将失败，因此自动化不会接受过时的发现。
- 在托管网络环境中遵守企业代理和受信任的证书设置。

<a id="write-clearer-vulnerability-reports"></a>

### 编写更清晰的漏洞报告

- 生成有来源支持的漏洞报告，将观察到的行为与未经验证的假设区分开来。
- 包括现实的概念验证限制、受影响的版本、安全边界和可行的补救指南。

<a id="0115-july-30-2026"></a>

## 0.1.15（2026年7月30日）

<a id="preserve-scan-results-when-the-repository-changes"></a>

### 当仓库更改时保留扫描结果

- 即使文件或仓库修订版在扫描运行时发生变化，仍将已完成的发现和报告与原始修订版或工作树快照相关联。
- 当所选代码更改或目标变得不可用时显示完成警告，而不是丢弃扫描结果。
- 将现有扫描存档，然后再将其输出目录重新用于另一次扫描。

<a id="apply-reviewed-finding-feedback"></a>

### 应用经过审查的发现反馈

- 当您将发现结果视为误报时，请记录原因。
- 将经过审查的误报决策带入同一目标的后续扫描中，而不将其应用于另一个检查或不相关的目标。
- 仅当先前的原因仍然适用于当前代码和安全控制时，才抑制重复出现的结果。

<a id="recover-valid-findings-without-overstating-coverage"></a>

### 在不夸大覆盖范围的情况下恢复有效的发现

- 当另一个发现、报告或强化工件格式错误时，保留有效的发现，并对跳过的数据显示警告。
- 删除重复的发现，并根据严重性、置信度和支持证据保留最有力的发现。
- 当 Codex 无法验证结果、审查收据或后续区域时，将覆盖范围标记为部分。
- 在 SARIF 导出中包含不完整的覆盖范围和延期审查警告。

<a id="keep-scan-settings-and-progress-visible"></a>

### 保持扫描设置和进度可见

- 通过标准和深度扫描保存选定的模型和推理工作，以便扫描历史记录和进度在重新加载时保持一致。
- 显示活动和已完成的独立深度扫描审核的数量以及结果整合开始的时间。
- 根据可用的工作人员能力调整标准扫描发现，同时保留一份范围内文件列表和一份候选审核通过。

<a id="support-more-repository-and-filesystem-layouts"></a>

### 支持更多仓库和文件系统布局

- 捕获工作树快照时包括嵌套的 Git 仓库。
- 保留范围内的文字文件路径并处理不区分大小写的 Windows 路径。
- 在扫描预检期间展开以 `~` 开头的已配置 `CODEX_HOME`。

<a id="0114-july-28-2026"></a>

## 0.1.14（2026年7月28日）

<a id="review-scan-history-and-recurring-findings"></a>

### 查看扫描历史记录和重复出现的结果

- 使用有限的结果页面和更清晰的状态详细信息过滤仓库、结果和扫描历史记录。
- 使用保存的设置重新运行扫描，并比较已完成的扫描，以区分新的、持续存在的、已解决的和未重新扫描的结果。
- 对同一仓库中的工作树进行分组，并使用稳定的仓库并跨视图查找身份。

<a id="define-repository-security-policy"></a>

### 定义仓库安全策略

- 使用 `$codex-security:define-security-policy` 查看或更新有关信任边界、安全不变量、可报告结果、严重性、排除和可接受风险的范围 `SECURITY.md` 指南。
- 应用最接近的策略文件，同时限制其大小并拒绝离开仓库的符号链接。

<a id="review-findings-before-tracking-them"></a>

### 在跟踪调查结果之前先对其进行审查

- 从已完成的扫描中选择最多 25 个结果，以在线性或 GitHub 问题中进行跟踪。
- 将选定的结果返回到 Codex 进行审查和批准，而不是直接从结果工作区创建问题。

<a id="run-standard-scans-with-a-simpler-workflow"></a>

### 使用更简单的工作流程运行标准扫描

- 使用一个确定性范围内文件列表和一个紧凑的候选分类账来进行标准仓库和范围路径扫描。
- 保留现有的清单、调查结果、覆盖范围、报告和 SARIF 输出，同时减少重复扫描阶段。

<a id="0113-july-25-2026"></a>

## 0.1.13（2026年7月25日）

<a id="review-findings-across-more-environments"></a>

### 审查更多环境中的发现

- 当受影响的代码是本地、内部、用于培训或未部署到生产中时，保留真实的安全发现。
- 使用部署和暴露上下文来校准严重性和置信度，而不是自动抑制发现。

<a id="0112-july-23-2026"></a>

## 0.1.12（2026年7月23日）

<a id="run-deeper-scans-with-clearer-progress"></a>

### 运行更深入的扫描，进度更清晰

- 运行深度扫描，协调整个仓库或选定目录中的工作人员。
- 将您的模型和推理设置带入委托扫描工作中。
- 在扫描之前和扫描期间查看预检结果、扫描进度、可用工作人员容量以及回退行为。

<a id="review-and-rerun-previous-scans"></a>

### 查看并重新运行以前的扫描

- 从安全扫描列表中打开当前和以前的扫描。
- 在结果工作区中重新打开保存的扫描，或重新运行它以刷新结果。
- 查看更清晰的完成状态以及更一致的查找详细信息和扫描历史记录。

<a id="configure-scans-with-fewer-interruptions"></a>

### 配置扫描以减少中断

- 从本机设置流程开始扫描，无需离开当前任务。
- 即使 Codex 处于全屏模式，也将扫描设置保留在侧面板中。
- 当您不需要时关闭安装并保留该首选项以供以后扫描。

<a id="review-and-remediate-validated-findings"></a>

### 审查并纠正经过验证的发现

- 将经过验证的低严重性发现保留在已完成的结果中。
- 在扫描、报告和导出中查看更一致的发现细节。
- 重试修复并将相关扫描上下文纳入后续修复中。

<a id="export-results-for-existing-security-workflows"></a>

### 导出现有安全工作流程的结果

- 将完成的结果导出为 JSON、CSV 或 SARIF。
- 在本地生成 SARIF 结果以进行代码扫描和安全工具集成。
- 在导出的格式中保留一致的查找详细信息。

### 直接运行报告工作流程

- 在深度扫描开始之前检查深度扫描阶段的技能、委派的工作人员和工作人员能力。

## 0.1.9（2026 年 6 月 18 日）

### 以更少的设置运行扫描

- 对 Git 仓库、单个文件夹或没有 Git 历史记录的代码库运行标准扫描。深度扫描还可以针对特定文件夹。
- 显式取消活动扫描，在没有其他设置提示的情况下恢复中断的扫描，并在开始并发深度扫描之前收到警告。
- 遵循更清晰的设置和进度状态，更紧凑的进度摘要和错误在您解决之前仍然可见。

<a id="export-portable-verifiable-results"></a>

### 导出可移植、可验证的结果

- 使用一致的完整扫描格式，其中包含清单、结构化结果、覆盖范围数据以及源自相同规范结果的 Markdown 报告。
- 将结果导出为 JSON、CSV 或 SARIF，以便分析、存档以及与其他安全工具集成。
- 更可靠地完成扫描，包括当 Windows 路径或扫描锁定影响文件系统访问时。

<a id="triage-and-track-existing-findings"></a>

### 分类并跟踪现有发现

- 根据当前代码库对来自扫描仪、建议、错误赏金报告、GitHub、Jira、Linear 或 Codex Security 结果的现有发现进行分类。分类工作流程返回有证据支持的判决和优先级操作队列。
- 跟踪 Linear、Jira 或 GitHub 问题中选定的经过验证的结果，或者在仓库满足咨询要求时创建私人草稿 GitHub 安全咨询。
- 在批准写入之前，请检查重复检查、源上下文、目标可见性以及确切的建议内容。 Codex 在创建或更新后读取结果进行验证。
