<a id="run-a-codex-security-scan"></a>

# 标准安全扫描

> 有关完整的文档索引，请参阅 [llms.txt](https://learn.chatgpt.com/llms.txt)。通过将 `.md` 附加到页面 URL 即可获得文档页面的 Markdown 版本。

从标准 Codex Security 扫描开始进行初步审查或例行仓库或组件评估。它运行一次完整扫描工作流程。

要进行更彻底的评估，请查看结果，然后运行 [深度扫描](deep-scans.zh-CN.md)。深度扫描需要更长的时间并且搜索范围更广。

<a id="choose-the-scan-area"></a>

## 选择扫描区域

在桌面应用程序中，打开 **安全性**，选择 **扫描**，然后选择 **+ 扫描**。选择现有仓库或其他文件夹，然后选择 **代码库**。

当您需要广泛的覆盖范围并且仓库是一个合理的审查单元时，请扫描整个仓库。对于单一仓库，当服务、包或组件具有明确的所有者和安全边界时，请选择一个文件夹。

您还可以从 Codex 对话开始扫描：

```text
使用 $codex-security:security-scan 扫描此仓库是否存在安全漏洞。
```

要将对话集中在特定文件夹上，请识别该组件：

```text
使用 $codex-security:security-scan 扫描此仓库是否存在安全漏洞，重点关注服务/计费组件。
```

对于大型单一仓库，从一个有意义的产品或服务边界开始。

<a id="configure-the-scan"></a>

## 配置扫描

为了获得最佳扫描质量，请使用 `gpt-5.6-sol` 和 `xhigh` 推理工作。

<WorkflowSteps>

1. 选择 **代码库** 并将 **深度扫描** 保持关闭。
2. 确认所选仓库、当前分支和最新版本。
3. 将 **扫描区域** 设置为整个仓库或选择一个文件夹。
4. 选择模型和推理工作。
5. 仅当它改变评论时才打开**额外的背景信息**。有用的上下文名称是攻击者控制的输入、信任边界、敏感操作或要优先考虑的特定区域。
6. 选择**开始扫描**。

</WorkflowSteps>

将 `SECURITY.md` 添加到仓库根以获得持久的安全指导。描述威胁模型、安全不变量、可报告的发现标准、排除和严重性上下文。添加嵌套 `SECURITY.md` 文件以获取特定于目录的指导。当策略发生冲突时，最接近代码的文件优先。 Codex Security 将这些文件视为策略上下文，而不是可执行指令。

使用 `AGENTS.md` 来获取支持的构建和验证命令以及其他仓库特定的指令。

<a id="let-the-phases-complete"></a>

## 让各个阶段完成

扫描按顺序运行这些阶段：

1. **威胁建模** 识别资产、入口点、信任边界和安全不变量。
2. **寻找发现** 检查所请求的代码是否有可能损坏的控制和源到汇路径。
3. **验证** 测试或以其他方式检查每个候选人并记录证据或证据差距。
4. **影响和路径分析** 评估每个候选人的现实路径、影响和严重性。
5. **报告** 记录经过验证的发现、覆盖范围和扫描元数据。可根据要求提供详细的每次发现报告。
6. **结构硬化** 根据要求分析结果集并创建设计指南。
7. **最终确定** 验证结构化扫描合同并生成 `report.md`，包括任何详细报告或强化指南的链接。

工作台显示活动扫描阶段以及插件报告的任何进度。选择 **查看活动** 以检查 Codex 任务。等待完整的结果，而不是判断早期候选人或因为一个阶段比另一阶段花费更长的时间而停止。

<a id="review-the-completed-scan"></a>

## 查看已完成的扫描

按以下顺序查看结果：

1. 确认目标、修订和扫描区域。
2. 阅读已审查的使用界面以及每个明确的推迟或后续区域。
3. 对于每个发现，检查根控制或接收器、攻击者控制的输入、验证方法、剩余不确定性、实际可达性、严重性原理和建议的补救措施。
4. 驳回那些证据不支持所声称的路径或影响的发现。
5. 在开始修复之前选择一项已接受的发现。

<a id="assess-a-first-scan"></a>

## 评估第一次扫描

在扫描之前，选择两到四个评估标准，例如独立发现、证据质量、误报或补救质量。如果您针对已知结果进行测试，请记录您是否将其提供给 Codex 还是在扫描中隐瞒。

记录仓库修订、插件版本、模型和推理工作。使用此基线可以比较代码、安全控制或扫描设置更改后的后续扫描。

<a id="choose-a-scan-cadence"></a>

## 选择扫描节奏

根据仓库的风险和团队解决问题的能力设置扫描节奏。在这些点进行扫描：

- **基线：** 当您加入仓库、获得组件所有权或需要新威胁模型的起点时，运行标准扫描。
- **代码更改：** [检查代码更改](code-changes.zh-CN.md) 当拉取请求或提交更改安全敏感代码或外部集成时。
- **定期审查：** 根据系统的暴露程度和代码更改的频率设置定期审核间隔。根据您的团队解决问题的能力进行调整。
- **修复后：** [修复并验证发现的结果](fix-findings.zh-CN.md)。确认问题不再重现并保留原始扫描以进行比较。

这些扫描触发器不会创建自动计划。

<a id="reopen-a-previous-scan"></a>

## 重新打开之前的扫描

打开 **安全性**，然后从 **扫描** 中选择保存的扫描以查看其结果、覆盖范围和可用的报告工件。要评估最新代码，请对同一仓库开始新的扫描。新的扫描不会取代早期的扫描或其工件。

<a id="use-the-results"></a>

## 使用结果

使用安全工作台查看结果、覆盖范围和后续区域，而无需检查原始 JSON。打开`report.md`当可用于完整扫描目录的可读入口点时。共享或存档时将目录放在一起：报告链接到详细报告`findings/`和结构强化指导`hardening/`当这些可选工件可用时。

在工作区后面，每次扫描都会保留 `scan-manifest.json`、`findings.json` 和 `coverage.json` 以用于自动化和集成。您通常不需要自己打开这些文件。

对于便携式工件或外部问题跟踪，请参阅 [导出或跟踪结果](export-findings.zh-CN.md)。
