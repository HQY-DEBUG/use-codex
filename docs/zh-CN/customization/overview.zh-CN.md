# 定制功能概览

> 有关完整的文档索引，请参阅 [llms.txt](https://learn.chatgpt.com/llms.txt)。通过将 `.md` 附加到页面 URL 即可获得文档页面的 Markdown 版本。

定制是您让 Codex 按照您团队的工作方式工作的方式。

在 Codex 中，定制来自于协同工作的几个层：

- **项目指导（`AGENTS.md`）** 用于持久指令
- **[回忆](memories.zh-CN.md)** 用于从之前的工作中学到的有用上下文
- **技能** 用于可重用的工作流程和领域专业知识
- **[模型上下文协议](../extend/mcp.zh-CN.md)** 用于访问外部工具和共享系统
- **[子智能体](../agent-configuration/subagents.zh-CN.md)** 用于将工作委派给专门的子智能体

这些是互补的，而不是竞争的。 `AGENTS.md` 塑造行为，记忆承载本地环境，技能包可重复流程，[模型上下文协议](../extend/mcp.zh-CN.md) 将 Codex 连接到本地工作区之外的系统。

<a id="agents-guidance"></a>

## 智能体指导

`AGENTS.md` 为 Codex 提供持久的项目指导，该指导与您的仓库一起移动并在智能体开始工作之前应用。保持较小。

将其用于您希望 Codex 每次在仓库中遵循的规则，例如：

- 构建和测试命令
- 回顾期望
- 特定于回购协议的约定
- 特定于目录的说明

当智能体对您的代码库作出错误假设时，请在 `AGENTS.md` 中更正它们，并要求智能体更新 `AGENTS.md` 以便修复持续存在。将其视为反馈循环。

**更新`AGENTS.md`：** 仅从重要的指令开始。整理定期审核反馈，将指南放在最近的适用目录中，并告诉智能体在您更正某些内容时更新 `AGENTS.md`，以便将来的会话继承修复。

<a id="when-to-update-agentsmd"></a>

### 何时更新 `AGENTS.md`

- **重复错误**：如果智能体重复犯同样的错误，则添加一条规则。
- **读书太多**：如果它找到了正确的文件但读取了太多文档，请添加路由指南（优先考虑哪些目录/文件）。
- **定期公关反馈**：如果您多次留下相同的反馈，请将其编码。
- **在GitHub**：在拉取请求注释中，使用请求标记 `@codex`（例如 `@codex add this to AGENTS.md`），以将更新委托给云聊天。
- **自动漂移检查**：使用 [计划任务](../automations.zh-CN.md) 运行定期检查（例如每天），查找指导差距并建议向 `AGENTS.md` 添加哪些内容。

将 `AGENTS.md` 与执行这些规则的基础设施配对：预提交挂钩、linter 和类型检查器可以在您发现问题之前捕获它们，因此系统可以更智能地防止重复出现错误。

Codex 可以从多个位置加载指导：Codex 主目录中的全局文件（对于作为开发人员的您）以及团队可以签入的特定于仓库的文件。靠近工作目录的文件优先。使用全局文件来决定 Codex 与您沟通的方式（例如，审查风格、详细程度和默认值），并使仓库文件专注于团队和代码库规则。

## 技能

技能为 Codex 提供可重复使用的功能，以实现可重复的工作流程。技能通常最适合可重用工作流程，因为它们支持更丰富的指令、脚本和参考，同时保持跨任务的可重用性。技能已加载并对智能体可见（至少是其元数据），因此 Codex 可以隐式发现并选择它们。这使得丰富的工作流程可用，而无需预先增加上下文。

使用技能文件夹在本地创作和迭代工作流程。如果工作流程已存在插件，请先安装它以重复使用经过验证的设置。当您想要跨团队分发自己的工作流程或将其与连接器捆绑时，请将其打包为 [插件](../build-plugins.zh-CN.md)。技能仍然是创作格式；插件是可安装的分发单元。

技能通常是 `SKILL.md` 文件加上可选脚本、参考和资产。

技能目录可以包含 `scripts/` 文件夹，其中包含 Codex 作为工作流程的一部分调用的 CLI 脚本（例如，种子数据或运行验证）。当工作流程需要外部系统（问题跟踪器、设计工具、文档服务器）时，将该技能与 [模型上下文协议](../extend/mcp.zh-CN.md) 配对。

示例 `SKILL.md`：

```md
---
名称：提交
描述：暂存并提交语义组中的更改。当用户想要提交、组织提交或在推送之前清理分支时使用。
---

1. 不要运行`git add .`。按用途将文件暂存在逻辑组中。
2. 分组为单独的提交：壮举→测试→文档→重构→杂务。
3. 编写与更改范围相匹配的简洁提交消息。
4. 保持每次提交的重点和可审查性。
```

使用技能：

- 可重复的工作流程（发布步骤、审核例程、文档更新）
- 团队特定的专业知识
- 需要示例、参考或帮助脚本的过程

技能可以是全局的（对于作为开发人员的您来说，在您的用户目录中）或特定于仓库的技能（对于您的团队来说，签入 `.agents/skills` 中）。当工作流程适用于该项目时，将回购技能放入 `.agents/skills` 中；使用您的用户目录来获取所有仓库中您想要的技能。

| 层 | 全局 | 仓库 |
| :----- | :------------------- | :--------------------------------------------- |
| 智能体 | `~/.codex/AGENTS.md` | `AGENTS.md` 位于仓库根或嵌套目录 |
| 仓库中的技能 | `~/.agents/skills` | `.agents/skills` |

Codex 采用渐进式披露技能：

- 它以用于发现的元数据（`name`、`description`）开始
- 仅当选择技能时才加载 `SKILL.md`
- 仅在需要时读取引用或运行脚本

技能可以显式调用，Codex也可以在任务与技能描述匹配时隐式选择技能。清晰的技能描述提高了触发的可靠性。

## MCP

MCP（模型上下文协议）是将 Codex 连接到外部工具和上下文提供程序的标准方式。它对于 Figma、Linear、GitHub 等远程托管系统或您的团队依赖的内部知识服务特别有用。

当 Codex 需要本地仓库之外的功能（例如问题跟踪器、设计工具、浏览器或共享文档系统）时，请使用 MCP。

一种思考方式：

- **主持人**: Codex
- **客户**：Codex内部的MCP连接
- **服务器**：外部工具或上下文提供者

MCP 服务器可以公开：

- **工具**（动作）
- **资源**（可读数据）
- **提示**（可重复使用的提示模板）

这种分离可以帮助您推理信任和能力边界。一些服务器主要提供上下文，而另一些服务器则提供强大的操作。

在实践中，MCP 在与技能配对时通常最有用：

- 技能定义工作流程并命名要使用的 MCP 工具

[模型上下文协议](../extend/mcp.zh-CN.md)

<a id="subagents"></a>

## 子智能体

您可以创建具有不同角色的不同智能体，并提示他们以不同的方式使用工具。例如，一个智能体可能运行特定的测试命令和配置，而另一个智能体则拥有 MCP 服务器来获取生产日志以进行调试。每个子智能体都保持专注并使用正确的工具来完成其工作。

[子智能体](../agent-configuration/subagents.zh-CN.md)

<a id="skills--mcp-together"></a>

## 技能+MCP一起

技能加上 MCP 是这一切的结合之处：技能定义可重复的工作流程，而 MCP 将它们连接到外部工具和系统。如果技能依赖于 MCP，请在 `agents/openai.yaml` 中声明该依赖关系，以便 Codex 可以自动安装和连接它（请参阅 [培养技能](../build-skills.zh-CN.md)）。
